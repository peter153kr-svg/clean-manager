# 운영 백업 실행 실패 조사 — 2026-10-27

판정: 운영 백업/복원 성공 미확인, 재실행 보류. 이번 작업에서는 운영 DB에 재접속하지 않았다.

## 읽기 전용 확인

- 운영 백업 Node 프로세스 0개, skyclean-production-* 컨테이너 0개.
- production-backup-summary-*.json 0개, 지정 폴더의 clean-manager-production-*.age 0개.
- 개인키 본문/비밀번호/PowerShell 전체 기록/고객 행/백업 원문은 조회하지 않았다.
- 기존 파일이나 잔여 자원을 삭제하지 않았다. 현재 잔여 자원이 없다는 사실만 확인했으며 과거 순간적인 운영 접속 유무는 소급 확정할 수 없다.

## 확인된 사실과 추정

`$backupProcess=null` 상태의 WaitForExit 오류는 시작 전 검사 예외나 프로세스 시작 실패 이후 나타나는 2차 오류다. 긴 PowerShell try/finally 및 후속 명령을 콘솔에 나눠 붙여넣으면 첫 예외 뒤에도 후속 줄이 독립 실행될 수 있다.

첫 예외 기록이 없으므로 자격증명 취소, User 검사 불일치, Start 실패, 명령 누락 중 실제 원인은 확정하지 못했다. node.exe 부재라고 단정하지 않는다. 긴 블록과 세션 변수에 의존한 설계가 사용성과 진단을 악화시킨 점은 확인했다.

## 단일 명령 준비 방식

대표님이 직접 연 콘솔에서 다음 준비 확인만 실행할 수 있도록 했다.

```powershell
node .\scripts\backup-console.mjs --prepare
```

비밀번호를 묻지 않고 DB/Docker/age 실행과 파일 생성을 하지 않는다. Node 버전, 대화형 콘솔 여부, 백엔드 파일 존재만 표시한다. `.ps1`, 실행 정책 변경, Bypass, 비밀번호 파일은 사용하지 않는다.

실제 실행 모드 `--run-production-backup`은 별도 재승인 후에만 사용한다. **이번에는 실행하지 않았다.** Host/User/Port 입력·검증, 명시적 BACKUP 확인, 숨김 비밀번호 입력을 하나의 Node 프로세스에서 수행한다. 수동 콘솔 입력의 IME/포커스 호환성은 아직 미확인이다.

백엔드는 spawn/close/error 이벤트로 시작 여부와 종료 코드를 확인한다. 실행 파일이 없으면 executable-not-found로 반환하며 null 객체에 WaitForExit를 호출하지 않는다. 자격증명은 메모리 UTF-8 Buffer와 익명 stdin으로만 전달한다. 원문 stdout/stderr를 표시하지 않고 오류 분류·종료 코드·허용된 요약 경로만 표시한다. 비밀번호 입력의 readline 출력과 입력 기록은 비활성화한다. 모든 메모리 복사본의 즉시 완전 소거를 보장하지는 않는다.

## 로컬 검증

런처 테스트 5/5 통과: 준비 모드의 무접속/무입력, 리디렉션 콘솔 실행 차단, 숨김 입력 비노출, 존재하지 않는 실행 파일의 시작 실패 분류, 합성 자격증명의 익명 stdin 전달. 실제 자격증명이나 DB를 사용하지 않았다. 준비 도구 검증은 운영 백업 성공을 의미하지 않는다.

기존 TLS/읽기 전용/바이너리 스트리밍/격리 복원/비밀값 로그 금지 조건은 유지한다. 개인키와 백업을 같은 PC에 보관하는 탈취·악성코드·랜섬웨어·디스크 고장 위험도 남아 있다. USB 및 운영 재실행은 하지 않았다.

최신 사용자 지시에 따라 독립 개발은 별도 브랜치에서 합성 데이터로 진행한다. 운영 마이그레이션/main 병합/운영 배포/고객 자동 메시지 금지는 유지한다.
