# AI 비서 독립 개발 결과 — 2026-10-27

브랜치: codex/ai-office-development. 백업과 무관하게 가능한 개발을 진행하라는 최신 지시에 따른다. 운영 접속/백업 재시도, 기존 홈페이지·CRM 코드, Supabase 운영 스키마, Vercel 설정, main 및 운영 배포는 변경하지 않았다.

## 구현

새 경로 `/ai-office-lab`과 순수 도메인 모듈 `src/lib/ai-office/engine.ts`를 추가했다. AI_OFFICE_DEV_MODE=synthetic 또는 Vercel Preview에서만 열리고 기존 로그인 보호를 유지한다. 운영 모드에서 404, 새 페이지는 noindex/nofollow다. 기존 사이드바/홈페이지 SEO는 수정하지 않았다.

| 직원 | 구현한 기능 | 제한 |
| --- | --- | --- |
| 일정 | 기존 SchedulePost 파서 재사용, 합성 이벤트 수신/수정/중복, 날짜·시간·현장·금액 분석, 검토/승인/제외, 이력, 목록/달력 | 규칙 기반. 실제 봇·수신함 DB·LLM 미연결 |
| 총괄실장 | 오늘·내일 승인 일정, 검토 대기, 시간 누락, 동일 시작시각 충돌, 직원 처리 상태 | 작업시간/이동시간 충돌까지 판단하지 않음. 자동 발송 없음 |
| 고객·매출 | jobs/sales와 같은 필드 형태의 예상액·확정 매출·수납·미수금, 일/주/월 집계 | 실제 CRM 조회/수정 없음. partial 수납액이 없으면 미수금 추정하지 않음 |
| 블로그·릴스 | 현장별 블로그 기획 목록, 4구간 릴스 촬영 구성, 검토 상태 | 완료 사실/동의를 만들어내지 않음. 게시/AI API/고객 메시지 없음 |

합성 데이터는 화면 메모리에만 존재하고 새로고침하면 초기화된다. 실제 고객정보 입력 금지. 승인 버튼도 화면 상태만 바꾸고 CRM 예약/매출을 확정하지 않는다. 운영 백업 데이터를 개발에 사용하지 않았다.

## 원칙

- 기준일은 Asia/Seoul이다. 오늘/내일/모레와 연도 경계를 처리한다.
- 연도 누락, 없는 날짜, 복수 날짜/금액, 모호한 오전·오후, 날짜 표현 불일치, 잘못된 금액 쉼표/단위 누락은 검토 대상으로 남긴다.
- 최신 revision만 초안에 반영하고 수정 이력을 보존한다. 중복/역순은 기존 승인 상태를 덮어쓰지 않으며 새 수정은 재검토한다.
- 예상액은 예약/진행 작업이며 확정 매출·수납과 더하지 않는다. 명시 수납액 또는 paid 상태만 수납 집계에 사용한다.
- 외부 통신/LLM 호출/개인정보 저장/자동 발송을 추가하지 않았다.

## 검증 결과

- 도메인/기존 텔레그램/런처/접속 정책 32/32 통과(새 도메인 11개 포함).
- AI 페이지 로컬 Auth/HTTP 4/4 통과: 비로그인 보호, 로그인 렌더링/4개 역할/noindex, 개발 모드 없을 때 404.
- 기존 CRM 합성 DB 및 Next HTTP 회귀 14/14 통과.
- Next 16.4.3 기본 Turbopack 빌드/TypeScript 및 지정 파일 ESLint 통과.

운영 .env 파일 없는 `.security-local/ai-office-validation` 복사본과 별도 로컬 Supabase clean-manager-security(API 56321/DB 56322)를 사용했다. 로컬 키는 메모리로만 전달했다. 테스트 후 임시 Auth 사용자/CRM 합성 행/검증 복사본/서버/로컬 서비스를 정리하고 원본 의존성은 유지한다.

Vercel Preview에는 배포하지 않았다. 실제 브라우저의 모든 클릭/레이아웃 검증도 미완료다. 빌드·SSR·순수 로직·HTTP 검증을 실제 봇/AI API/영속 큐 연결과 구분한다.
